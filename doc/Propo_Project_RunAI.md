# 1. Project Overview

## 1.1 Project Background

ปัจจุบันบริเวณอ่างเก็บน้ำภายในมหาวิทยาลัยพะเยาเป็นพื้นที่ที่มีผู้ใช้งานสำหรับการออกกำลังกายและการวิ่งเป็นประจำ โดยผู้ที่วิ่งแต่ละคนมีความแตกต่างกันทั้งด้านประสบการณ์ ระยะทางที่สามารถวิ่งได้ ความเร็วในการวิ่ง ความถี่ในการฝึก และเป้าหมาย เช่น การวิ่งเพื่อสุขภาพ การเพิ่มระยะทาง การพัฒนาความเร็ว หรือการเตรียมตัวสำหรับการแข่งขัน

สำหรับผู้ที่ต้องการพัฒนาความสามารถในการวิ่งหรือต้องการวางแผนการฝึกวิ่ง ปัจจุบันสามารถใช้แอปพลิเคชันและแหล่งข้อมูลต่าง ๆ เพื่อช่วยในการบันทึกและติดตามผลการวิ่ง เช่น Strava และแอปพลิเคชันสำหรับการฝึกวิ่ง รวมถึงการค้นหาข้อมูลจากเว็บไซต์และสื่อสังคมออนไลน์ โดยผู้ใช้งานสามารถบันทึกข้อมูล เช่น ระยะทาง เวลา และประวัติการวิ่ง เพื่อนำมาใช้ติดตามพัฒนาการของตนเอง และใช้เป็นข้อมูลประกอบการวางแผนการฝึก

อย่างไรก็ตาม การนำข้อมูลการวิ่งของตนเองมาพิจารณาร่วมกับเป้าหมาย ความสามารถ และข้อจำกัดด้านเวลา เพื่อกำหนดแผนการฝึกที่เหมาะสมยังคงต้องอาศัยการตัดสินใจและการวางแผนของผู้ใช้งานเอง เช่น การกำหนดวันวิ่ง วันพัก ระยะทาง ประเภทของการวิ่ง และระดับความหนักของการฝึก ซึ่งผู้ใช้งานอาจต้องค้นหาข้อมูลจากหลายแหล่งและนำมาประกอบกัน ทำให้การวางแผนการฝึกที่เหมาะสมกับแต่ละบุคคลอาจมีความซับซ้อน

นอกจากนี้ ผู้ใช้งานสามารถบันทึกข้อมูลการวิ่งผ่านแอปพลิเคชัน Strava เช่น ระยะทาง เวลา และประวัติการวิ่ง โดยข้อมูลจะถูกจัดเก็บไว้ในบัญชีของผู้ใช้งาน และสามารถนำข้อมูลดังกล่าวมาใช้ติดตามพัฒนาการและประกอบการวางแผนการฝึกวิ่งในครั้งต่อไป

จากบริบทดังกล่าว จึงเกิดแนวคิดในการพัฒนา RunAI: วางแผนการวิ่งด้วย AI ซึ่งเป็น Web Application ที่นำข้อมูลของผู้ใช้งาน เช่น ข้อมูลพื้นฐาน ความสามารถในการวิ่ง เป้าหมาย และข้อมูลการวิ่ง มาใช้ประกอบการวิเคราะห์ โดยนำเทคโนโลยีปัญญาประดิษฐ์เข้ามาช่วยสร้างคำแนะนำและแผนการฝึกวิ่งที่สอดคล้องกับข้อมูลและเป้าหมายของผู้ใช้งาน รวมถึงช่วยให้ผู้ใช้งานสามารถบันทึกและติดตามประวัติการวิ่งของตนเองได้อย่างเป็นระบบ

## 1.2 Current Working Process

1. กำหนดเป้าหมายการวิ่ง : ผู้ใช้งานกำหนดเป้าหมายของตนเอง เช่น เพิ่มระยะทาง พัฒนาความเร็ว วิ่งเพื่อสุขภาพ หรือเตรียมตัวสำหรับการแข่งขัน
2. ค้นหาข้อมูลและคำแนะนำ : ผู้ใช้งานค้นหาข้อมูลเกี่ยวกับการฝึกวิ่งจากเว็บไซต์ สื่อสังคมออนไลน์ หรือแอปพลิเคชันที่เกี่ยวข้อง เพื่อนำข้อมูลมาใช้ประกอบการวางแผน
3. จัดทำแผนการฝึกด้วยตนเอง : ผู้ใช้งานนำข้อมูลที่ค้นหาได้มาพิจารณาร่วมกับความสามารถและเป้าหมายของตนเอง เพื่อกำหนดวันวิ่ง วันพัก ระยะทาง ประเภทการวิ่ง และระดับความหนักของการฝึก
4. ออกกำลังกายตามแผนที่กำหนด : ผู้ใช้งานออกวิ่งตามแผนการฝึกที่จัดทำไว้
5. บันทึกข้อมูลการวิ่ง : หลังจากวิ่ง ผู้ใช้งานบันทึกข้อมูล เช่น ระยะทาง เวลา และข้อมูลการวิ่งอื่น ๆ ผ่านแอปพลิเคชัน เช่น Strava โดยข้อมูลจะถูกจัดเก็บไว้ในบัญชีของผู้ใช้งาน
6. ตรวจสอบและติดตามผลการวิ่ง : ผู้ใช้งานตรวจสอบข้อมูลการวิ่งย้อนหลังและเปรียบเทียบกับเป้าหมายหรือแผนการฝึกที่กำหนดไว้
7. ปรับแผนการฝึก : หากผลการวิ่งไม่เป็นไปตามเป้าหมาย หรือผู้ใช้งานต้องการพัฒนาต่อ ผู้ใช้งานจะนำข้อมูลที่บันทึกไว้มาพิจารณาและปรับแผนการฝึกด้วยตนเอง
8. สิ้นสุดรอบการฝึกและเริ่มวางแผนรอบถัดไป : เมื่อสิ้นสุดช่วงการฝึก ผู้ใช้งานประเมินผลการวิ่งและนำข้อมูลที่ได้มาใช้ประกอบการกำหนดเป้าหมายหรือแผนการฝึกครั้งต่อไป

## 1.3 Project Idea

RunAI: วางแผนการวิ่งด้วย AI เป็น Web Application ที่พัฒนาขึ้นเพื่อช่วยผู้ที่ต้องการพัฒนาความสามารถในการวิ่งหรือวางแผนการฝึกวิ่ง โดยระบบจะนำข้อมูลของผู้ใช้งาน เช่น อายุ น้ำหนัก ส่วนสูง ระดับประสบการณ์ เป้าหมายการวิ่ง และข้อมูลประวัติการวิ่ง เช่น ระยะทาง เวลา มาใช้ประกอบการวิเคราะห์และวางแผนการฝึก

---

## 1.4 Expected Changes

เมื่อมี RunAI คาดว่าจะเกิดการเปลี่ยนแปลงดังนี้ : 

- มีระบบช่วยวิเคราะห์ข้อมูลการวิ่งและให้คำแนะนำตามข้อมูลของผู้ใช้งาน
- AI ช่วยสร้างแผนการฝึกตามข้อมูลพื้นฐาน เป้าหมาย และประวัติการวิ่ง
- ผู้ใช้งานสามารถจัดเก็บและติดตามข้อมูลการวิ่งภายในระบบเดียว
- ข้อมูลประวัติการวิ่งสามารถนำกลับมาใช้ประกอบการวิเคราะห์และวางแผนครั้งถัดไป
- ลดขั้นตอนที่ผู้ใช้งานต้องนำข้อมูลจากหลายแหล่งมาวิเคราะห์และวางแผนด้วยตนเอง

# 2. Problem & Motivation

## 2.1 Current Problems

อธิบายปัญหาที่เกิดขึ้นในกระบวนการปัจจุบันอย่างชัดเจน

ไม่ควรเขียนเพียงว่า:

> “ระบบเดิมไม่มีประสิทธิภาพ”  
> “ทำงานไม่สะดวก”  
> “ใช้เวลานาน”

แต่ควรอธิบายว่า **ไม่มีประสิทธิภาพอย่างไร สะดวกน้อยตรงไหน และเสียเวลาในขั้นตอนใด**

ตัวอย่างประเด็น:

- ข้อมูลซ้ำซ้อน
- ข้อมูลสูญหาย
- ข้อมูลไม่เป็นปัจจุบัน
- ค้นหาข้อมูลยาก
- ต้องกรอกข้อมูลเดิมหลายครั้ง
- ไม่สามารถติดตามสถานะได้
- ไม่ทราบว่าใครเป็นผู้รับผิดชอบ
- การอนุมัติล่าช้า
- เกิดความผิดพลาดจากการกรอกข้อมูล
- ข้อมูลกระจายอยู่หลายแหล่ง
- การสื่อสารระหว่างผู้เกี่ยวข้องไม่ชัดเจน
- ต้องจัดทำรายงานด้วยตนเอง

### Problem 1

**ปัญหา:**  

> ข้อมูลและคำแนะนำเกี่ยวกับการฝึกวิ่งกระจายอยู่หลายแหล่ง ทำให้ผู้ใช้งานต้องค้นหาและรวบรวมข้อมูลด้วยตนเองก่อนนำมาวางแผนการฝึก

**สถานการณ์หรือตัวอย่างที่พบ:**  

> ค้นหาข้อมูลเกี่ยวกับประเภทการวิ่ง ระยะทาง หรือวิธีการฝึกจากเว็บไซต์ สื่อสังคมออนไลน์ และแอปพลิเคชันต่าง ๆ แล้วต้องนำข้อมูลจากแต่ละแหล่งมาพิจารณาและจัดทำแผนการฝึกด้วยตนเอง

### Problem 2

**ปัญหา:**  

> ผู้ใช้งานต้องวิเคราะห์ข้อมูลการวิ่งและตัดสินใจปรับแผนการฝึกด้วยตนเอง ทำให้การนำข้อมูล เช่น ระยะทาง เวลา มาใช้ประกอบการวางแผนอาจมีความซับซ้อน

**สถานการณ์หรือตัวอย่างที่พบ:**  

> หลังจากบันทึกผลการวิ่งในแต่ละครั้ง ผู้ใช้งานต้องตรวจสอบข้อมูลย้อนหลังและพิจารณาด้วยตนเองว่าควรเพิ่มหรือลดระยะทาง ปรับความเร็ว หรือเปลี่ยนรูปแบบการฝึกในครั้งถัดไปอย่างไร

### Problem 3

**ปัญหา:**  

> ข้อมูลประวัติการวิ่งและข้อมูลเป้าหมายของผู้ใช้งานยังไม่ได้ถูกนำมารวมเป็นข้อมูลประกอบการวางแผนในกระบวนการเดียวกัน ทำให้ผู้ใช้งานต้องนำข้อมูลจากหลายส่วนมาพิจารณาด้วยตนเอง

**สถานการณ์หรือตัวอย่างที่พบ:**  

> ผู้ใช้งานอาจมีข้อมูลประวัติการวิ่งอยู่ใน Strava ขณะที่ข้อมูลเป้าหมายและแผนการฝึกอาจถูกกำหนดหรือจัดเก็บแยกต่างหาก เมื่อต้องวางแผนการฝึกครั้งใหม่จึงต้องนำข้อมูลเหล่านี้มาพิจารณาร่วมกันด้วยตนเอง

## 2.2 Causes of the Problems

วิเคราะห์ว่า **ทำไมปัญหาเหล่านั้นจึงเกิดขึ้น**

ตัวอย่าง:

- ไม่มีระบบกลางสำหรับจัดเก็บข้อมูล
- ใช้หลายเครื่องมือที่ไม่เชื่อมโยงกัน
- ไม่มี Workflow ที่ชัดเจน
- ไม่มีการกำหนดสิทธิ์ผู้ใช้งาน
- ไม่มี Validation
- กระบวนการบางส่วนยังทำด้วยเอกสาร
- ไม่มีระบบติดตามสถานะหรือแจ้งเตือน

| Problem | Cause |
|---|---|
| Problem 1:ข้อมูลและคำแนะนำเกี่ยวกับการฝึกวิ่งกระจายอยู่หลายแหล่ง | ไม่มีระบบกลางที่รวบรวมข้อมูลและคำแนะนำเกี่ยวกับการฝึกวิ่ง ทำให้ผู้ใช้งานต้องค้นหาและรวบรวมข้อมูลจากหลายแหล่งด้วยตนเอง |
| Problem 2:ผู้ใช้งานต้องวิเคราะห์ข้อมูลการวิ่งและตัดสินใจปรับแผนด้วยตนเอง | ไม่มีระบบที่ช่วยวิเคราะห์ข้อมูลการวิ่งและนำข้อมูลมาใช้ในการแนะนำแผนการฝึก ทำให้ผู้ใช้งานต้องพิจารณาข้อมูล เช่น ระยะทาง เวลา ด้วยตนเอง |
| Problem 3:ข้อมูลประวัติการวิ่งและข้อมูลเป้าหมายไม่ได้ถูกนำมารวมเป็นข้อมูลประกอบการวางแผนในกระบวนการเดียวกัน| ข้อมูลการวิ่งและข้อมูลเป้าหมายอาจอยู่แยกจากกัน และไม่มีกระบวนการที่นำข้อมูลทั้งสองส่วนมาวิเคราะห์ร่วมกัน ทำให้ผู้ใช้งานต้องนำข้อมูลมาพิจารณาด้วยตนเอง |

- เวลา
- ค่าใช้จ่าย

- คุณภาพของบริการ

| Problem | Impact |
|---|---|
| Problem 1: ข้อมูลและคำแนะนำเกี่ยวกับการฝึกวิ่งกระจายอยู่หลายแหล่ง | ผู้ใช้งานต้องใช้เวลาในการค้นหาและรวบรวมข้อมูลจากหลายแหล่ง และอาจทำให้การนำข้อมูลมาประกอบการวางแผนทำได้ไม่สะดวก |
| Problem 2: ผู้ใช้งานต้องวิเคราะห์ข้อมูลการวิ่งและตัดสินใจปรับแผนด้วยตนเอง | ผู้ใช้งานต้องใช้เวลาและความพยายามในการวิเคราะห์ข้อมูล เช่น ระยะทาง เวลา อาจไม่สามารถนำข้อมูลเหล่านั้นมาใช้วางแผนการฝึกได้อย่างเหมาะสม |
| Problem 3: ข้อมูลประวัติการวิ่งและข้อมูลเป้าหมายไม่ได้ถูกนำมารวมเป็นข้อมูลประกอบการวางแผนในกระบวนการเดียวกัน | ผู้ใช้งานต้องนำข้อมูลจากแต่ละส่วนมาพิจารณาร่วมกันด้วยตนเอง ทำให้การติดตามพัฒนาการและการปรับแผนการฝึกในครั้งถัดไปไม่เป็นระบบ |

## 2.5 Why Is a Software System Needed?

ปัญหาของกระบวนการวางแผนการวิ่งมีข้อมูลหลายส่วนที่ต้องนำมาพิจารณาร่วมกัน เช่น ข้อมูลพื้นฐานของผู้ใช้งาน เป้าหมายการวิ่ง และประวัติการวิ่ง ซึ่งปัจจุบันผู้ใช้งานต้องค้นหา วิเคราะห์ และจัดการข้อมูลด้วยตนเองจากหลายแหล่ง ดังนั้น Software System สามารถเข้ามาช่วยรวบรวมและจัดการข้อมูลเหล่านี้ให้อยู่ในระบบเดียว ทำให้สามารถค้นหาและเรียกดูข้อมูลย้อนหลังได้อย่างเป็นระบบ

นอกจากนี้ ระบบสามารถนำข้อมูลของผู้ใช้งานและประวัติการวิ่งมาใช้ประกอบการวิเคราะห์ด้วย AI เพื่อสร้างคำแนะนำและแผนการฝึกที่สอดคล้องกับเป้าหมายของผู้ใช้งาน รวมถึงสามารถนำข้อมูลการวิ่งที่ผ่านมาไปใช้ประกอบการวางแผนการฝึกในครั้งถัดไปได้ ซึ่งช่วยลดขั้นตอนที่ผู้ใช้งานต้องนำข้อมูลจากหลายแหล่งมาวิเคราะห์และวางแผนด้วยตนเอง

ดังนั้น การพัฒนา RunAI ในรูปแบบ Software System จะช่วยให้ การจัดเก็บข้อมูล การติดตามประวัติการวิ่ง การวิเคราะห์ข้อมูล และการวางแผนการฝึก สามารถดำเนินการภายในระบบเดียวกัน และทำให้ข้อมูลที่เกิดขึ้นจากการวิ่งแต่ละครั้งสามารถนำกลับมาใช้ประโยชน์ในกระบวนการฝึกครั้งต่อไปได้อย่างเป็นระบบ

## 2.6 Motivation for Developing the Project

พวกเราเลือกพัฒนา RunAI: วางแผนการวิ่งด้วย AI เนื่องจากการวิ่งเป็นกิจกรรมที่สามารถพบได้เป็นประจำบริเวณอ่างเก็บน้ำภายในมหาวิทยาลัยพะเยา และผู้ที่วิ่งแต่ละคนมีเป้าหมายและความสามารถที่แตกต่างกัน การวางแผนการฝึกจึงจำเป็นต้องพิจารณาข้อมูลของแต่ละบุคคลให้เหมาะสม

จากกระบวนการปัจจุบัน ผู้ใช้งานต้องค้นหาข้อมูลเกี่ยวกับการฝึกวิ่งจากหลายแหล่ง บันทึกและติดตามผลการวิ่งผ่านแอปพลิเคชัน เช่น Strava รวมถึงนำข้อมูลที่ได้มาวิเคราะห์และปรับแผนการฝึกด้วยตนเอง กระบวนการดังกล่าวเกิดขึ้นซ้ำทุกครั้งที่ผู้ใช้งานออกวิ่งและต้องการพัฒนาการฝึก ทำให้มีโอกาสในการนำ Software System และ AI เข้ามาช่วยลดขั้นตอนการวิเคราะห์และวางแผน

พวกเราจึงมองเห็นโอกาสในการพัฒนาระบบที่สามารถรวบรวมข้อมูลของผู้ใช้งานและประวัติการวิ่ง แล้วนำข้อมูลเหล่านั้นมาใช้ประกอบการวิเคราะห์และสร้างคำแนะนำหรือแผนการฝึกที่สอดคล้องกับเป้าหมายของแต่ละบุคคล โดยคาดว่าจะช่วยให้ผู้ใช้งานสามารถจัดการข้อมูล ติดตามพัฒนาการ และวางแผนการฝึกได้อย่างเป็นระบบมากขึ้น

> ผู้ใช้งานมีเควสการวิ่งที่เปิดให้ทำในวันปัจจุบัน และต้องการทำเควสแล้วส่งผลการวิ่งให้ระบบ

**Goal:**  

> บันทึกผลการวิ่งและส่งเควสเพื่อให้ระบบตรวจสอบว่าเควสสำเร็จหรือไม่ และปลดล็อกเควสของวันถัดไป

**Main Flow:**

1. ผู้ใช้งานเข้าสู่ระบบ RunAI
2. ระบบแสดงเควสของวันปัจจุบัน หากวันนั้นไม่มีเควส ระบบแสดงข้อความ “วันนี้ไม่มีเควส”
3. ผู้ใช้งานทำเควสการวิ่งภายในเวลา 00:00–23:59
4. ผู้ใช้งานเลือกส่งเควสและกรอกระยะทางกับเวลา
5. ผู้ใช้งานสามารถแนบรูปผลการวิ่งจาก Strava ได้ แต่ไม่บังคับ
6. ระบบตรวจสอบข้อมูลการวิ่งและตรวจระยะทางเทียบกับระยะทางเป้าหมายของเควส
7. หากระยะทางถึงเป้าหมาย ระบบบันทึกผลเป็นสำเร็จและปลดล็อกเควสของวันถัดไป
8. หากระยะทางไม่ถึงเป้าหมาย ระบบไม่อนุญาตให้ส่งเป็นสำเร็จ และผู้ใช้งานสามารถเลือก “ทำเควสไม่สำเร็จ” พร้อมระบุเหตุผล
9. เมื่อส่งผลเควสแล้ว ผู้ใช้งานไม่สามารถแก้ไขผลการส่งได้

**Expected Result:**  

> ผลการวิ่งและสถานะของเควสถูกจัดเก็บในระบบ และระบบสามารถดำเนินการกับเควสของวันถัดไปตามผลของเควสปัจจุบันได้

## Scenario 3: [สร้างตารางการฝึกด้วย AI]

**User:**  

> นักวิ่ง / ผู้ใช้งาน

**Starting Situation:**  

> ผู้ใช้งานมีข้อมูลพื้นฐาน เป้าหมายการวิ่ง และประวัติการวิ่งอย่างน้อย 1 ครั้งในระบบ และต้องการให้ AI สร้างตารางการฝึก

**Goal:**  

> ขอให้ AI วิเคราะห์ข้อมูลและสร้างตารางการฝึกที่สอดคล้องกับเป้าหมายของผู้ใช้งาน

**Main Flow:**

1. ผู้ใช้งานเข้าสู่ระบบ RunAI
2. ผู้ใช้งานกำหนดเป้าหมายการวิ่ง
3. ระบบตรวจสอบว่าผู้ใช้งานมีประวัติการวิ่งอย่างน้อย 1 ครั้ง
4. ระบบรวบรวมข้อมูลพื้นฐาน เป้าหมาย และประวัติการวิ่งที่จำเป็น
5. ระบบส่งข้อมูลที่เกี่ยวข้องให้ AI วิเคราะห์
6. AI สร้างตารางการฝึกปัจจุบัน 1 ตาราง โดยแบ่งเป็นเควสรายวัน
7. ระบบแสดงตารางการฝึกและเควสของวันปัจจุบันให้ผู้ใช้งาน

**Expected Result:**  

> ผู้ใช้งานได้รับตารางการฝึกที่ AI สร้างจากข้อมูลของตนเอง โดยมีเควสรายวันและสามารถเริ่มทำเควสที่ปลดล็อกได้

---

## Scenario 4: [ติดตามเควสและปรับตารางการฝึก]

**User:**  

> นักวิ่ง / ผู้ใช้งาน

**Starting Situation:**  

> ผู้ใช้งานกำลังใช้ตารางการฝึกปัจจุบันและมีเควสของวันนั้นที่ต้องทำ

**Goal:**  

> ทำเควส ส่งผล และให้ระบบนำผลของเควสไปใช้กำหนดเควสของวันถัดไป

**Main Flow:**

1. ผู้ใช้งานเข้าสู่ระบบและดูเควสของวันปัจจุบัน
2. หากวันนั้นไม่มีเควส ระบบแสดง “วันนี้ไม่มีเควส” และผู้ใช้งานไม่ต้องส่งผล
3. หากมีเควส ผู้ใช้งานทำเควสและส่งระยะทางกับเวลา
4. หากระยะทางถึงเป้าหมาย เควสถูกบันทึกเป็นสำเร็จ และตารางการฝึกเดิมยังคงใช้งานต่อ
5. หากผู้ใช้งานทำเควสไม่สำเร็จ ผู้ใช้งานเลือกสถานะไม่สำเร็จและระบุเหตุผล
6. ระบบส่งผลของเควสที่ไม่สำเร็จให้ AI วิเคราะห์ทันที
7. AI ปรับเควสและตารางเฉพาะส่วนที่ยังไม่เกิดจากวันปัจจุบันเป็นต้นไป
8. เควสของวันที่ผ่านมาไม่ถูกแก้ไข และเควสที่ไม่สำเร็จถูกเก็บเป็นประวัติ
9. ระบบแสดงตารางใหม่และให้ผู้ใช้งานกด “ยอมรับแผน”
10. เมื่อผู้ใช้งานยอมรับแผน เควสของวันถัดไปจึงใช้ข้อมูลจากตารางใหม่

**Expected Result:**  

> ผู้ใช้งานสามารถทำเควสและส่งผลได้ หากเควสไม่สำเร็จระบบจะปรับตารางส่วนที่เหลือด้วย AI และผู้ใช้งานสามารถยอมรับตารางใหม่เพื่อดำเนินการต่อ

- ใครใช้
- ใช้เพื่ออะไร
- ทำงานโดยสรุปอย่างไร
- Feature นี้ช่วยแก้ Problem ใด

# 9. Data Requirements

ระบุ **ข้อมูลสำคัญที่ระบบจำเป็นต้องจัดเก็บ** และเหตุผลที่ต้องใช้ข้อมูลนั้น

> ในขั้น Proposal ยังไม่ต้องออกแบบ Table, Column, Primary Key หรือ Foreign Key

| Data Group | ตัวอย่างข้อมูลที่ต้องใช้ | ใช้เพื่ออะไร |
|---|---|---|
| ข้อมูลผู้ใช้งาน | ชื่อ, อีเมล, รหัสผ่าน, อายุ, น้ำหนัก, ส่วนสูง, ระดับประสบการณ์การวิ่ง | ใช้ระบุตัวผู้ใช้งานและเป็นข้อมูลพื้นฐานสำหรับการวิเคราะห์และวางแผนการฝึก |
| ข้อมูลเป้าหมายการวิ่ง | เป้าหมาย, ระยะทางเป้าหมาย, เวลาเป้าหมาย, วันที่ต้องการบรรลุเป้าหมาย, สถานะเป้าหมาย | ใช้กำหนดทิศทางในการวางแผนและให้ AI สร้างหรือปรับตารางให้สอดคล้องกับเป้าหมาย |

# 11. Acceptance Criteria

## Feature: [จัดการบัญชีและข้อมูลผู้ใช้งาน]

- ผู้ใช้สามารถสมัครสมาชิกและเข้าสู่ระบบด้วยข้อมูลที่ถูกต้อง
- ระบบต้องตรวจสอบข้อมูลที่จำเป็นก่อนสร้างบัญชี
- เมื่อเข้าสู่ระบบสำเร็จ ระบบต้องแสดงข้อมูลของผู้ใช้ที่เข้าสู่ระบบ
- ผู้ใช้สามารถแก้ไขข้อมูลส่วนตัวของตนเองได้
- ระบบต้องไม่อนุญาตให้ผู้ใช้เข้าถึงข้อมูลส่วนตัวของผู้ใช้อื่น

---
## Feature: [กำหนดเป้าหมายการวิ่ง]

- ผู้ใช้สามารถกำหนดเป้าหมายการวิ่งของตนเองได้
- ระบบต้องตรวจสอบข้อมูลที่จำเป็นก่อนบันทึกเป้าหมาย
- เมื่อบันทึกสำเร็จ ระบบต้องจัดเก็บเป้าหมายและเชื่อมโยงกับผู้ใช้
- ผู้ใช้สามารถแก้ไขเป้าหมายของตนเองได้

---
## Feature: [บันทึกข้อมูลการวิ่ง]

- ผู้ใช้สามารถกรอกข้อมูลการวิ่งหลังจากวิ่งเสร็จได้
- ระบบต้องตรวจสอบว่ามี วันที่ ระยะทาง และเวลา ก่อนบันทึก
- ระบบต้องไม่อนุญาตให้บันทึกข้อมูลหากข้อมูลที่จำเป็นไม่ครบ
- เมื่อดำเนินการสำเร็จ ระบบต้องจัดเก็บข้อมูลการวิ่งไว้ในประวัติของผู้ใช้
- ข้อมูลการวิ่งต้องถูกเชื่อมโยงกับผู้ใช้ที่เป็นเจ้าของข้อมูล

---
## Feature: [AI สร้างตารางการฝึก]

- ผู้ใช้สามารถขอให้ AI สร้างตารางการฝึกได้เมื่อมีประวัติการวิ่งอย่างน้อย 1 ครั้ง
- ระบบต้องตรวจสอบเงื่อนไขข้อมูลก่อนส่งคำขอให้ AI
- เมื่อ AI สร้างตารางสำเร็จ ระบบต้องสร้างตารางการฝึกปัจจุบัน 1 ตาราง
- ตารางต้องแบ่งเป็นเควสรายวัน และแต่ละวันต้องมีไม่เกิน 1 เควส
- ระบบต้องไม่สร้างตารางจากข้อมูลของผู้ใช้รายอื่น

---
## Feature: [ทำและส่งเควสรายวัน]

- ระบบต้องแสดงเควสของวันปัจจุบันเมื่อมีเควส
- หากวันนั้นไม่มีเควส ระบบต้องแสดงข้อความ “วันนี้ไม่มีเควส”
- เควสต้องเปิดให้ทำตั้งแต่เวลา 00:00 และหมดเวลา 23:59
- ผู้ใช้สามารถส่งระยะทางจริงและเวลาจริงของการวิ่งได้
- ผู้ใช้สามารถแนบรูปผลการวิ่งจาก Strava ได้โดยไม่บังคับ
- ระบบต้องใช้ระยะทางเป็นเกณฑ์หลักในการตรวจว่าเควสสำเร็จหรือไม่
- หากระยะทางจริงถึงหรือมากกว่าระยะทางเป้าหมาย ระบบต้องอนุญาตให้ส่งเควสเป็นสำเร็จ
- หากระยะทางจริงน้อยกว่าระยะทางเป้าหมาย ระบบต้องไม่อนุญาตให้ส่งเป็นสำเร็จ และต้องแสดงการแจ้งเตือนว่า “เควสยังไม่ผ่าน”
- เมื่อผู้ใช้ส่งผลเควสแล้ว ระบบต้องไม่อนุญาตให้แก้ไขผลการส่ง

---
## Feature: [ติดตามและปรับตารางการฝึก]

- หากเควสสำเร็จ ระบบต้องปลดล็อกเควสของวันถัดไปตามตารางเดิม
- หากผู้ใช้เลือกทำเควสไม่สำเร็จ ระบบต้องให้ผู้ใช้ระบุเหตุผล
- หากผู้ใช้ไม่ส่งเควสภายใน 23:59 ระบบต้องถือว่าเควสไม่สำเร็จจากการหมดเวลา
- เมื่อเควสไม่สำเร็จ ระบบต้องส่งข้อมูลผลและเหตุผลที่เกี่ยวข้องให้ AI วิเคราะห์ทันที
- เมื่อ AI วิเคราะห์สำเร็จ ระบบต้องปรับเฉพาะเควสที่ยังไม่เกิดในตาราง
- เควสและผลการส่งของวันที่ผ่านมาแล้วต้องไม่ถูกแก้ไข
- หลังจาก AI ปรับตาราง ระบบต้องแสดงตารางใหม่และให้ผู้ใช้กดยอมรับแผน
- ผู้ใช้ต้องไม่สามารถแก้รายละเอียดเควสในตารางใหม่ได้โดยตรง

---
## Feature: [จบหรือดำเนินเป้าหมายต่อ]

- เมื่อผู้ใช้บรรลุเป้าหมายก่อนวันสิ้นสุด ระบบต้องแสดงตัวเลือก “วิ่งตามตารางต่อ” และ “จบเป้าหมายนี้”
- หากผู้ใช้เลือกวิ่งตามตารางต่อ ระบบต้องใช้ตารางเดิมต่อโดยไม่ปรับตารางอัตโนมัติ
- หากผู้ใช้เลือกจบเป้าหมาย ระบบต้องเปลี่ยนสถานะเป้าหมายเป็นเสร็จสิ้นและให้ผู้ใช้สามารถสร้างเป้าหมายใหม่ได้


# 12. Constraints

|---|---|---|
| ระยะเวลาในการพัฒนา | ระบบต้องพัฒนาภายในระยะเวลาที่กำหนดของโครงการ | ต้องจัดลำดับความสำคัญของ Feature และเน้นฟังก์ชันหลักของ RunAI ก่อน |
| Platform | ระบบพัฒนาเป็น Web Application และใช้งานผ่าน Web Browser | ผู้ใช้ต้องมีอุปกรณ์ที่สามารถเปิด Web Browser และเชื่อมต่ออินเทอร์เน็ตได้ |
| Internet Connection | ระบบจำเป็นต้องเชื่อมต่ออินเทอร์เน็ตเพื่อใช้งาน Web Application และเรียกใช้ AI API | หากไม่มีอินเทอร์เน็ต ผู้ใช้อาจไม่สามารถบันทึกข้อมูลหรือใช้งานฟังก์ชัน AI ได้ตามปกติ |
| การบันทึกข้อมูลการวิ่ง | ผู้ใช้เป็นผู้กรอกข้อมูลการวิ่งด้วยตนเองหลังจากวิ่งเสร็จ ไม่ได้ดึงข้อมูลจากอุปกรณ์หรือ Strava โดยอัตโนมัติ | ระบบต้องออกแบบแบบฟอร์มให้รองรับการกรอกข้อมูลการวิ่งและตรวจสอบข้อมูลก่อนบันทึก |
| การแนบรูป Strava | ผู้ใช้สามารถแนบรูปผลการวิ่งจาก Strava ได้ แต่ระบบไม่อ่านหรือวิเคราะห์ข้อมูลจากรูป | รูปทำหน้าที่เป็นไฟล์แนบประกอบการส่งเควสเท่านั้น |
| AI API ภายนอก | การวิเคราะห์และสร้างหรือปรับตารางการฝึกต้องอาศัย AI API จากระบบภายนอก | หาก API ไม่พร้อมใช้งาน มีข้อจำกัดด้านการใช้งาน หรือเกิดข้อผิดพลาด ฟังก์ชัน AI อาจไม่สามารถทำงานได้ |
| ข้อมูลของผู้ใช้งาน | ข้อมูลการวิ่งและข้อมูลส่วนตัวเป็นข้อมูลของผู้ใช้งานแต่ละราย | ระบบต้องแยกข้อมูลตามผู้ใช้งานและไม่อนุญาตให้เข้าถึงข้อมูลของผู้ใช้งานรายอื่น |
| ความถูกต้องของข้อมูลที่ผู้ใช้กรอก | ข้อมูลการวิ่งถูกกรอกโดยผู้ใช้งานเอง จึงขึ้นอยู่กับความถูกต้องของข้อมูลที่ป้อนเข้าสู่ระบบ | ระบบต้องมีการตรวจสอบข้อมูลพื้นฐานก่อนจัดเก็บและนำไปวิเคราะห์ |
| ขอบเขตของ AI | AI ใช้สำหรับวิเคราะห์ข้อมูลการวิ่งและสร้างหรือปรับคำแนะนำและแผนการฝึก ไม่ใช่ระบบวินิจฉัยหรือรักษาทางการแพทย์ | ระบบต้องสื่อสารขอบเขตการใช้งานของคำแนะนำจาก AI อย่างชัดเจน |

# 15. Example End-to-End Scenario

ปั้นจั่นเป็นนักศึกษาที่ต้องการพัฒนาการวิ่ง โดยมีเป้าหมายที่จะวิ่งระยะทาง 5 กิโลเมตรได้ดีขึ้น ปั้นจั่นสมัครสมาชิก กรอกข้อมูลพื้นฐาน กำหนดเป้าหมาย และบันทึกประวัติการวิ่งอย่างน้อย 1 ครั้ง

จากนั้นปั้นจั่นขอให้ RunAI สร้างตารางการฝึก ระบบนำข้อมูลพื้นฐาน เป้าหมาย และประวัติการวิ่งไปให้ AI วิเคราะห์ และ AI สร้างตารางการฝึกปัจจุบัน 1 ตาราง โดยแบ่งเป็นเควสรายวัน

วันแรก ปั้นจั่นได้รับเควส Easy Run 5 กิโลเมตร และมีเวลาในการทำเควสตั้งแต่ 00:00 ถึง 23:59 เมื่อวิ่งเสร็จ ปั้นจั่นกดส่งเควสและกรอกระยะทางกับเวลา โดยสามารถแนบรูปผลการวิ่งจาก Strava ได้ แต่ไม่จำเป็นต้องแนบ

หากปั้นจั่นวิ่งได้ 5 กิโลเมตรหรือมากกว่า ระบบจะบันทึกเควสเป็นสำเร็จและปลดล็อกเควสของวันถัดไปตามตารางเดิม แต่หากวิ่งไม่ถึง 5 กิโลเมตร ระบบจะแจ้งว่า “เควสยังไม่ผ่าน” และปั้นจั่นต้องเลือก “ทำเควสไม่สำเร็จ” พร้อมระบุเหตุผล จากนั้น AI จะวิเคราะห์ผลและปรับเฉพาะเควสที่ยังไม่เกิดในตาราง

เมื่อ AI สร้างตารางใหม่ ระบบจะแสดงตารางที่ปรับแล้ว และปั้นจั่นต้องกดยอมรับแผนก่อนจึงจะใช้ตารางใหม่นั้น หากวันใดไม่มีเควส ระบบจะแสดง “วันนี้ไม่มีเควส” และไม่ต้องส่งผล

หากปั้นจั่นบรรลุเป้าหมายก่อนวันสิ้นสุด ระบบจะแสดงตัวเลือกให้เลือกว่าจะวิ่งตามตารางต่อจนถึงวันสิ้นสุด หรือจบเป้าหมายนี้เพื่อสร้างเป้าหมายใหม่ กระบวนการของเป้าหมายปัจจุบันจะสิ้นสุดเมื่อปั้นจั่นเลือกจบเป้าหมายหรือถึงวันสิ้นสุดของตาราง
